# AI context and evaluation

Generate concise guidance from approved definitions and reachable fields. Curate synonyms and example queries; expose ambiguity rather than inventing business meaning. DMA v2 context follows reviewed derived Query View lineage to accepted gold columns, including filter/join/grouping population dependencies. Explicitly select a topic for topic-specific eligibility; hashes bind its effective definition and field selections. Aggregation is not declassification. See [the executable contract](omni-ai-context.md).

Current approximate metadata budgets are 75K characters per topic and 100K for topic-selection summaries, not a fixed field count. Context guidance is nondeterministic, not security enforcement. Model context does not guarantee precedence over topic context. Test actual configuration, repeated questions, personas and source/result parity.

Preserve server-managed `ai_context_patch`; never author its contents. Check rendered context after parent drift. Approved values and examples must pass disclosure controls. Missing meaning, incorrect modeling and AI configuration are different repair paths.

Freeze independent questions and expected definitions/personas before candidate
results. Use repeated-trial comparison to retain provider/settings, complete
context hash and the original trial denominator. A missing trial or a confident
wrong metric fails. Imported structured observations remain distinct from live
provider identity, prose truth, effective access and business acceptance.

Sources: [AI optimization](https://docs.omni.co/modeling/develop/ai-optimization), [AI context](https://docs.omni.co/modeling/models/ai-context), [answer quality](https://docs.omni.co/guides/ai/improve-ai-answer-quality).
