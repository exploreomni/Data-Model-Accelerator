# Synthetic billing migration exercise

This is invented evaluation data and a simulation contract, not a customer definition, real export, security approval or permission to deploy.

Raw source: Snowflake database DMA_SIM, schema BRONZE, tables BILLING_INVOICE_CDC, BILLING_PAYMENT_CDC, BILLING_CREDIT_CDC, BILLING_CUSTOMER_HISTORY. Connection synthetic_billing_snowflake maps to that database and UTC session timestamps. Every row in raw-data.json maps to the same-named source object. IDs are nonempty ASCII letters/digits and contain no delimiters; amounts are integer cents encoded as text. ISO timestamp strings mean UTC instants. Raw history intervals are inclusive start/exclusive end, with null end open-ended.

Invoice and ledger change events are full after-images, ordered by source_seq within (tenant_id, invoice_id) or (tenant_id, entry_id). arrival_seq is arrival order only. Exact repeated versions are replay; conflicting payloads for one version are invalid. Select the greatest source version before processing DELETE tombstones. Raw replicas retain all events for this exercise. Normalize status by trimming and lowercasing. All invoices, including drafts, currencies and historical report dates, belong in the reusable model. No correction or report date may silently filter the shared model.

Current posted payment and credit entries are summed separately per tenant/invoice/currency before joining invoices. Do not join individual payment and credit rows together. Currency mismatches are errors, not opportunities for implicit conversion. Net invoice cents equal gross minus discount (null discount means zero) minus posted credits. Paid invoice cents equal posted payments; a missing ledger total is zero. The exercise permits zero net invoices and does not clamp values or invent exchange rates. Customer segment is from the same tenant/customer effective at invoice issued_at; absent history yields Unknown without dropping the invoice. Overlapping matching histories are invalid.

Business invoice_date is America/Chicago local date of issued_at. The dashboard defaults to posted invoices, currency USD, invoice_date >= 2026-09-01 and < 2026-10-01. These are semantic/report filters, not global warehouse row restrictions. Every query requires a tenant persona A or B. A missing/unknown persona is denied in the local simulator. The accepted exercise definition of payment_rate is SUM(paid_cents)/NULLIF(SUM(net_cents),0), after selected filters and grouping. No averaging or summing row ratios. Money display divides cents by 100, separately from amount calculations. Empty population has count0, net/paid0 and null rate under this exercise contract.

Required report scenarios: A USD September total; A USD September by segment and daily; A USD September selected segment SMB; A EUR September total; B USD September total; A USD August total; A USD September zero-net invoices only; A USD empty date interval. Also validate all gold rows against independent invoice-level expectations, including draft/out-of-period/other-currency records, replay invariance and shuffled arrival order.

Preserve original Looker asset names/IDs and field mappings in lineage. Translate the selected logic to native Snowflake bronze/silver/gold scripts and Omni semantic YAML. Current-source compatibility and independently specified intended behavior must both be reported; disagreements need explicit explanation. Local simulation is authorized. No live warehouse, BI tenant, credentials, publication or deployment is in scope.
