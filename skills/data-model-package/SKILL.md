# Package the current work

Delegated workers consume the coordinator's bounded task packet and selected
contracts under [targeted context](../data-model-accelerator/references/agent-context.md).
They do not recursively load the full workflow or repeat intake. The coordinator
retains responsibility for stage gates, approvals and complete coverage.

When coordinating this stage directly, load the sibling [Data Model Accelerator](../data-model-accelerator/SKILL.md)
and its [staged workflow](../data-model-accelerator/references/staged-engagement.md).
Require the complete main skill. Resume the same engagement and reuse the selected
audience, deliverables and current stage records.

Follow [delivery experience](../data-model-accelerator/references/delivery-experience.md).
Reuse the existing `START_HERE.html` or selected Markdown fallback as the one
authoritative working entrypoint. Offer at most three primary choices: Data model,
Code & files and Validation, showing only what the stage and audience permit.
Place full inventory, detailed validation and audit behind progressive detail
links; keep material blockers visible. Maintain one current design document
bound to canonical design/decision records, with required layer documentation
and dictionary linked beneath it. Do not create a portal or summary per milestone.

Check the `packaging` stage. A design-only review is a valid delivery; do not
generate code to fill an unrequested category. Refresh material and presentation
bindings, then use the shared [review surface](../data-model-accelerator/references/review-surface.md)
and delivery helpers. Include the guided HTML, scoped ERD/dictionary/layer docs,
selected artifact files and transparent pending decisions/evidence.

For existing repositories, package a focused patch with pinned source and
runtime/dependency requirements; include a complete reference snapshot only when
requested and permitted. Preserve required runtime files and tests. Disclose
unavailable dependencies instead of claiming a reference subset is runnable.
Keep generated, local, native and accepted readiness separate and scope-bound.

Present local design review as host-reported human review when that is the actual
assurance. The default local candidate path needs no signing service; packaging
must not upgrade its recorded scope bindings into authenticated release approval.

Asset filters change the view, not export or approval scope. Respect artifact
dependencies, portable links and audience/disclosure controls. Record actual
prepared files and verify the ZIP. Package integrity is not native validation or
release approval; preserve original evidence when creating a smaller export.
Refresh the live entrypoint, but keep prior exports and manifests immutable; each
new export has its own portable entrypoint snapshot. Preserve the exporter's
category paths, hashes, audience restrictions and dependency requirements.

Use concise chat milestones about outcome or learning, next action and material
blockers. Persist decisions in canonical records. Finish with one primary link
to the current entrypoint, the outcome, material limits and the next action.
