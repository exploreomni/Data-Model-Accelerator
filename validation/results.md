The subscription assessment was performed by an independent subagent using the skill and a separate raw exercise, in a temporary workspace. It proposed a model, ERD, refactoring plan and diagnostic SQL while distinguishing observed behavior from uncertain intent. It did not infer a canonical MRR definition, source version policy, successful reconciliation or warehouse readiness from one aggregate export. This single exercise supports the intended behavior on that case; it is not a cross-host benchmark.

The invoice mutations demonstrate concrete detection:

- Removing temporal join conditions produced 12 rows instead of eight.
- Omitting the tenant join condition produced five cross-tenant dimension joins.
- Removing a segment filter preserved the unfiltered output but changed a filtered result from two invoices to six.
- Selecting arrival order instead of source sequence regressed a corrected amount.
- Filtering deletes before ranking resurrected a deleted invoice.

The harness also rejects altered row-level expectations when grand totals stay unchanged, missing input files, conflicting source versions, overlapping or missing customer history, and missing registered checks.

Read [the full synthetic check report](synthetic-validation.json) and [fixture assumptions](../skills/data-model-accelerator/examples/CASE.md). The supporting review-package checker checks declared evidence integrity and completeness; it neither verifies evidence authenticity nor grants approval.

Read [the source-specialist exercise](specialist-smoke.md) for actual task identities, archived handoffs and the observed warehouse/semantic distinctions. This exercise tested the source extraction stage; separate warehouse/semantic architect runs, native semantic generation, independent full-model QA and customer acceptance were not completed on this fixture.

A separate checker review identified two false-success paths: removing the specialist-dispatch association could bypass its validation, and replacing the source root with a symlink could redirect source verification. Both were fixed. Four regression cases cover association removal, orphaned result evidence, source-root replacement and redirected source ancestors; the current suite includes those cases. These integrity checks still do not authenticate authorship, prove declared semantics or grant promotion authority.

The raw-catalogue addition is required context for physical design and review completeness. The earlier source-specialist exercise did not collect warehouse metadata and remains a source-only assessment; it cannot satisfy this new requirement. Catalogue tests use synthetic metadata exports with explicit scope, identity, timestamp, nested column paths, hashes and bindings. A successful catalogue check does not establish that raw export rows were normalized correctly or that the reference denominator contains every actual source: source interpretation and independent QA must establish those facts. No Snowflake, Databricks or BigQuery catalogue/profiling query was executed against a live service.

**Production qualification remains open.** No real source repository, native target compiler, warehouse role/policy enforcement, deployed CDC/incremental model, representative load/cost test, or customer acceptance was validated. The skill has documented packaging guidance for the named agent hosts, but no end-to-end compatibility run on the other hosts has been performed.
